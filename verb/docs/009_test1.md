# Verb: `test1`

- **Kind:** canonical
- **Availability:** workspace root only (modules use `verb/test_only`)
- **`--dry-run`:** `runbox .live -- ./verb/test1.d/l1 '<filter>'`

### Command

```bash
./verb/test1 <nextest-filter-expression>
```

Runs only the matching tests inside the container: the globally-installed `runbox` engine executes `verb/test1.d/l1` with the filter as a positional argument. The layer runs `cargo nextest run --workspace --all-features --no-fail-fast -E "<filter>"`. No doc tests or clippy — use `./verb/test` for the full suite.

### Notes

`verb/test1 <filter>` is the **mandatory** choice for targeted verification at workspace scope. Running `./verb/test` (full suite) to check a single test wastes the full nextest + doc-test + clippy cycle. The container-only invariant (`module/claude_profile/docs/invariant/009_container_only_test_execution.md`) applies to both forms.

The filter is a nextest **filter expression** (`-E` syntax), e.g. `test(name_substring)` or `package(claude_storage)`. It travels as a positional argument to the payload — no environment variable involved.

For a single module, prefer the module's own targeted verb: `cd module/<name> && ./verb/test_only <substring>` (positional name substring, not `-E` syntax).

`--dry-run` (first argument) prints the delegated command and exits 0 — no tests run.

### Example

```bash
# Run a single test by name:
./verb/test1 'test(test_config_get_existing_key)'

# Run every test in one crate:
./verb/test1 'package(claude_storage)'

# Dry run (prints command, no execution):
./verb/test1 --dry-run
```
