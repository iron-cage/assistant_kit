# Subcommand: mcp

Configure and manage MCP servers.

### Usage

```
claude mcp [command]
```

### Sub-subcommands

10 total (plus the generic commander.js `help [command]`, omitted as
boilerplate) — an earlier revision of this doc omitted `login`/`logout`
entirely; corrected against `claude mcp --help` on v2.1.220:

| Command | Description |
|---------|-------------|
| `add [options] <name> <commandOrUrl> [args...]` | Add an MCP server (stdio or HTTP) |
| `add-from-claude-desktop [options]` | Import MCP servers from Claude Desktop (Mac/WSL only) |
| `add-json [options] <name> <json>` | Add an MCP server (stdio or SSE) with a JSON string |
| `get <name>` | Get details about an MCP server. Unapproved `.mcp.json` servers show as "⏸ Pending approval" and are not connected to; approved servers are health-checked |
| `list` | List configured MCP servers. Same pending-approval/health-check behavior as `get` |
| `login [options] <name>` | Authenticate with an MCP server (HTTP, SSE, or claude.ai connector) |
| `logout <name>` | Clear stored OAuth credentials for an MCP server |
| `remove [options] <name>` | Remove an MCP server |
| `reset-project-choices` | Reset all approved/rejected project-scoped (.mcp.json) servers within this project |
| `serve [options]` | Start the Claude Code MCP server (expose Claude Code as MCP) |

### Description

Full MCP (Model Context Protocol) server lifecycle management. Supports adding
servers via command-line arguments, JSON configuration, or import from Claude
Desktop. Servers can use stdio or HTTP transport.

Examples:
```
# Add HTTP server:
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

# Add stdio server with env vars:
claude mcp add -e API_KEY=xxx my-server -- npx my-mcp-server

# Import from Claude Desktop:
claude mcp add-from-claude-desktop
```

The `serve` sub-subcommand starts Claude Code itself as an MCP server,
allowing other MCP clients to connect to it.

### Sub-subcommand Options

#### `claude mcp add`

| Option | Description |
|--------|-------------|
| `-t`, `--transport <transport>` | Transport type: `stdio`, `sse`, `http` (default: stdio) |
| `-s`, `--scope <scope>` | Config scope: `local`, `user`, or `project` (default: local) |
| `-e`, `--env <env...>` | Set environment variables (e.g. `-e KEY=value`) |
| `-H`, `--header <header...>` | Set WebSocket headers |
| `--client-id <clientId>` | OAuth client ID for HTTP/SSE servers |
| `--client-secret` | Prompt for OAuth client secret (or set `MCP_CLIENT_SECRET`) |
| `--callback-port <port>` | Fixed port for OAuth callback |

#### `claude mcp add-from-claude-desktop`

| Option | Description |
|--------|-------------|
| `-s`, `--scope <scope>` | Config scope: `local`, `user`, or `project` (default: local) |

#### `claude mcp add-json`

| Option | Description |
|--------|-------------|
| `-s`, `--scope <scope>` | Config scope: `local`, `user`, or `project` (default: local) |
| `--client-secret` | Prompt for OAuth client secret (or set `MCP_CLIENT_SECRET`) |

#### `claude mcp login`

| Option | Description |
|--------|-------------|
| `--no-browser` | Print the authorization URL instead of opening a browser (for SSH/headless sessions — paste the redirect URL back when prompted) |

#### `claude mcp logout`

No options beyond `-h`/`--help`.

#### `claude mcp remove`

| Option | Description |
|--------|-------------|
| `-s`, `--scope <scope>` | Config scope — if not specified, removes from whichever scope it exists in |

#### `claude mcp serve`

| Option | Description |
|--------|-------------|
| `-d`, `--debug` | Enable debug mode |
| `--verbose` | Override verbose mode setting from config |
