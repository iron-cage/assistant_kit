# Type: Tag

> **Status: 📋 planned** — designed, not yet implemented. This instance is the authoritative contract for implementation.

### Scope

- **Purpose**: Define Tag — a normalized label attached to accounts for pool partitioning.
- **Responsibility**: Documents the tag value format, normalization, set semantics on Account, and the `role`-field migration.
- **In Scope**: Value charset and length, normalization rules, set semantics, CLI list form.
- **Out of Scope**: Filtering semantics (→ [Tag Filter (004)](004_tag_filter.md)); rotation gate placement (→ [algorithm/004](../algorithm/004_eligibility_gates.md) Gate 11); storage field layout (→ [schema/002](../schema/002_account_json.md) `tags` field); CLI surface (→ [feature/075](../feature/075_account_tags.md)).

### Definition

A short normalized string labeling an [Account (001)](001_account.md) as a member of an operational pool (e.g. `kimi_pool`, `ci`, `personal`). Tags carry no behavior of their own — meaning is assigned by whoever partitions the fleet. An Account carries a *set* of tags: unordered, deduplicated, no intrinsic limit on count.

Purely a selection concern: tags never alter switch-time behavior (env vars, credentials) — that remains owned by [Backend (006)](006_backend.md) and [Provider (005)](005_provider.md).

### Validation

- Charset: `[a-z0-9_-]` only; 1–64 characters.
- Input is lowercased before validation; anything still outside the charset is rejected loudly (exit 1 naming the offending tag), never silently normalized away.
- Within a set: duplicates are collapsed; serialized order is sorted (deterministic files, clean diffs).
- CLI list form: comma-separated (`tags::kimi_pool,ci`); empty items rejected.

### Relationships

Referenced by [Tag Filter (004)](004_tag_filter.md) include/exclude sets; carried by [Account (001)](001_account.md); consumed by rotation eligibility Gate 11 ([algorithm/004](../algorithm/004_eligibility_gates.md)). CLI write/list/filter surface: [feature/075](../feature/075_account_tags.md).

**`role` migration**: the legacy free-form `role` string field on Account is superseded by tags. Migration: a non-empty `role` value is converted to a tag (lowercased, sanitized to the tag charset) on first tag write to that account; the `role` field is then removed from `{name}.json`. No standalone migration pass — conversion is lazy, per-account.

### Serialization

JSON array of strings, field `tags`, in `{name}.json` ([schema/002](../schema/002_account_json.md)). Absent field ≡ empty set.
