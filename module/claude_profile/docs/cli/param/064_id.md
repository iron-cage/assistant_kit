# Parameter: 64. `id::`

> **Narrowed scope** (Feature 035): `id::` no longer appears on `.model.select` — that command is retired and its subprocess-model pinning is now `model::` (with `scope::subprocess`) on the unified [`.model`](../command/007_model.md) command; see [076_model_value.md](076_model_value.md). `id::` remains live and unchanged on `.provider.select`, documented below.

Activates set mode on `.provider.select`, writing the global inference provider (`provider` key) to `~/.clr/config.toml`'s user tier. When provided, activates set mode; when absent, `.provider.select` operates in read (get) mode unless `reset::1` is set.

- **Default:** *(omit)* — get mode; reads current preference from `~/.clr/config.toml`
- **Constraints:** Any non-empty string; any provider name (e.g., `anthropic`, `kimi`) — no allow-list
- **Purpose:** Write a provider name to `~/.clr/config.toml` for use by account rotation Gate 10.

**Values:**

Any non-empty provider name is accepted (free-form, no allow-list) — e.g., `anthropic`, `kimi`, `moonshot`.

**Validation:** Non-empty check at write time only. No validity check beyond non-empty — any string is accepted since provider is a free-form label, not a filter.

**Error cases:**
- `id::` (empty value) → exit 1; stderr: `id:: must be a non-empty provider name`
- `id::VALUE reset::1` together → exit 1; stderr: `id:: and reset::1 are mutually exclusive`

**Examples:**

```bash
clp .provider.select id::kimi           # select the kimi inference provider globally
```

**Notes:**
- `id::` sets the single global provider config value — never a filter, never derived; only this manual write changes it (see [param 073](073_inference_provider.md), [algorithm/004](../../algorithm/004_eligibility_gates.md) Gate 10).
- The selected preference persists until explicitly reset with `reset::1` on the same command.
- For subprocess model pinning (the former `.model.select id::`), see [`model::`](076_model_value.md) on the unified `.model` command.
