# Parameter: 83. `add::`

Comma-separated list of tags to union into an account's existing tag set on `.account.tag`.

- **Default:** *(omit)*
- **Constraints:** Same item rules as [`tags::`](082_tags.md) — lowercased, `[a-z0-9_-]`, 1–64 chars, no empty items. Mutually exclusive with `tags::` and with `remove::`.
- **Purpose:** Grow an account's tag set incrementally without restating tags it already carries.

**Behavior:** Listed tags are merged into the existing set (duplicates collapse, result sorted). Adding a tag the account already carries is a no-op for that item. On the account's first tag write, a non-empty legacy `role` value is converted to a tag and merged too ([type/003](../../type/003_tag.md) migration rule).

**Examples:**

```text
clp .account.tag name::alice@acme.com add::ci          → set gains 'ci'
clp .account.tag name::alice@acme.com add::ci,staging  → set gains both
clp .account.tag name::X,Y add::ci                     → comma-list batch: both accounts gain 'ci'
```

**Error cases:**

```text
clp .account.tag name::X add::ci remove::ci  → exit 1: one operation per invocation
clp .account.tag name::X add::Bad!Tag        → exit 1: invalid tag 'bad!tag'
```

**See Also:** [082_tags.md](082_tags.md) (replace form), [084_remove.md](084_remove.md) (inverse operation).
