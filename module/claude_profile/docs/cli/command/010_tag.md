# Commands: Tag

Tag inventory command — lists every distinct tag known to the credential store.

---

### Command: 22. `.tags`

> **Status: 📋 planned** — specified by [feature/075](../../feature/075_account_tags.md); not yet implemented.

Lists every distinct [Tag](../../type/003_tag.md) in the credential store — the union of tags carried by accounts (`tags` array in `{name}.json`) and tags referenced by Identity Tag Filters (`_filter_*` include/exclude sets) — one sorted row per tag with usage counts. A tag referenced only by a filter still appears with an account count of `0`; that asymmetry is exactly the typo hazard the filter write-time guard warns about.

-- **Parameters:** [`format::`](../param/002_format.md)
-- **Exit:** 0 (success, including empty result) | 1 (usage: unknown parameter, unsupported format) | 2 (runtime: credential store unreadable)

**Syntax:**

```bash
clp .tags
clp .tags format::json
```

| Parameter | Type | Default | Purpose |
|-----------|------|---------|---------|
| `format::` | [`OutputFormat`](../type/002_output_format.md) | `text` | Output format — `text` and `json` only |

**Columns:**

| Column | Content |
|--------|---------|
| Tag | The tag itself (rows sorted lexicographically) |
| Accounts | Count of accounts whose `tags` array contains it |
| Filters | Count of `_filter_*` files referencing it (in include or exclude) |

**Algorithm (4 steps):**
1. Scan all account profiles (`{name}.json`) in the credential store; collect each `tags` array — absent field ≡ empty set ([schema/002](../../schema/002_account_json.md))
2. Scan all `_filter_{hostname}_{user}` files ([schema/009](../../schema/009_identity_filter_json.md)); collect every include and exclude set
3. Union all collected tags; for each, count carrying accounts and referencing filter files
4. Render the sorted table (or JSON array of `{"tag": …, "accounts": N, "filters": N}`); when the union is empty print `(no tags)` and exit 0

**Examples:**

```bash
clp .tags
# Tag        Accounts  Filters
# ci         3         1
# kimi_pool  2         2
# personal   1         1

clp .tags format::json
# [{"tag":"ci","accounts":3,"filters":1},{"tag":"kimi_pool","accounts":2,"filters":2},{"tag":"personal","accounts":1,"filters":1}]

clp .tags        # untagged store
# (no tags)

clp .tags format::table
# exit 1: format:: must be text or json
```

**Notes:**
- A row with `Accounts = 0` and `Filters > 0` means some Identity's filter names a tag no account carries — a non-empty include built from such tags can never match ([feature/076](../../feature/076_identity_tag_filter.md)'s typo guard warns at write time; this listing is where the operator confirms it).
- Read-only — never mutates account profiles or filter files.
- `(no tags)` exits 0: an untagged fleet is a valid state, not an error (zero-migration adoption, [feature/075](../../feature/075_account_tags.md) AC-16).
