# CLI Parameter: --dir

Set the working directory for the Claude Code subprocess. The runner
changes to this directory before invoking claude.

- **Type:** [`DirectoryPath`](../type/02_directory_path.md)
- **Alias:** `--to` (ergonomic companion for `--from` cross-loading workflows)
- **Default:** current working directory
- **Command:** [`run`](../command/01_run.md)
- **Group:** [Runner Control](../param_group/02_runner_control.md)
- **Validation:** requires a value; `--dir` at end of argv → error. For `run`/`ask` the directory must exist at invocation time: a nonexistent path fails fast with `Error: [Runner] working directory does not exist: <path> (--dir/--to must name an existing directory)` and exit 1 — before the concurrency gate, journal, or spawn (`--dry-run` exempt; BUG-491)
- **JSON Key:** `"dir"`

```sh
clr "Fix bug" --dir /path/to/project
```

**Note:** When `--dir` appears multiple times, the last value wins.

**Note:** A nonexistent `--dir`/`--to` used to be misdiagnosed as "claude binary
not found" (the subprocess spawn's NotFound error was attributed to the binary,
triggering an npm-install hint and the retry ladder). The fail-fast validation
above names the real problem instead (BUG-491).
