# CLI Command: ps

### Description

List all running Claude Code processes and queued `clr` waiters in two plain-style tables showing per-session PID, elapsed time, CPU%, RAM, working directory, and last-known task. Kernel state and execution mode are reported by the conditional `Flags` column rather than columns of their own (see § Session Flags); both remain selectable via `--columns`/`--wide`. A third, conditional table reports sessions that ended since the last `clr ps` call (see § Session Snapshot & Temporal Diff). Use `clr ps` to identify active sessions before `clr kill`, or to monitor concurrency gate queue depth.

-- **Parameters:** `--mode`, `--columns`, `--wide`, `--pid`, `--inspect`
-- **Exit Codes:** 0 (success) | 1 (error)
-- **Modes:** table (default), inspect

### Syntax

```sh
clr ps [OPTIONS]
```

### Parameters

| # | Parameter | Type | Default | Description |
|---|-----------|------|---------|-------------|
| 58 | [`--mode`](../param/058_mode.md) | enum | `all` | Filter sessions by execution mode (`all`/`interactive`/`print`/`query`) |
| 59 | [`--columns`](../param/059_columns.md) | string | 7 default cols | Comma-separated list of column keys to display |
| 60 | [`--wide`](../param/060_wide.md) | bool | false | Show all 11 columns (convenience shorthand) |
| 68 | [`--pid`](../param/068_pid.md) | string | — | Comma-separated PIDs; restrict active table to matching sessions only |
| 69 | [`--inspect`](../param/069_inspect.md) | bool | false | Switch output to key:value record format showing all 12 attributes per session |

The flags `--help` and `-h`, and the positional token `help`, print subcommand help and exit 0.

**Algorithm (5 steps):**
1. Scan `/proc` for running `claude` processes (excluding self); collect per-process metrics from `/proc/{pid}/stat`, `/proc/{pid}/status`, and session JSONL files.
2. Read the previous `clr ps` snapshot from `$CLR_PS_STATE_DIR` (default `~/.clr/ps/last_snapshot.json`), if one exists (see § Session Snapshot & Temporal Diff).
3. Compute session flags (👈🆕🖨🔌⚡🕰🐘🧟⚠🐳) per row — 🆕 from step 2's snapshot, the rest from step 1's metrics; apply `--mode` and `--pid` filters.
4. Read `$CLR_GATE_DIR` for gate state files; probe recorded-PID liveness via the shared `gate::pid_alive()` predicate (required contract per INV-012: `/proc/{pid}/stat` readable, state ∉ {`Z`}, thread-group leader of the same recorded incarnation — never bare PID-number occupancy); delete orphaned files.
5. Render active sessions table, queued processes table, and Ended Since Last Check table (or inspect blocks if `--inspect`); print legend when flags present; write the current process list as the new snapshot (replacing step 2's file — happens even under `--inspect`); exit 0.

### Output Format

Two plain-style tables printed consecutively. Each table is preceded by a titled
caption rule line (e.g., `─── Active Sessions · 3 running (1 interactive, 1 print, 1 query) ──────`)
that names the table and shows the item count. The column header row follows the caption.

1. **Active Sessions** — caption: `Active Sessions · N running (I interactive, P print, Q query)`
   when `--mode` is `all` (the default), where `I`, `P`, and `Q` are counts of the active
   rows classified as interactive, print, and query respectively (`I + P + Q == N`; see §
   Mode Detection for the per-row classification rule). When `--mode` is
   `interactive`, `print`, or `query`, every row already shares one mode, so the breakdown
   is omitted and the caption is the plain `Active Sessions · N running`. Default
   columns: `#`, `PID`, `Elapsed`, `CPU%`, `RAM`, `Absolute Path`, `Task`. Optional
   columns (hidden by default): `State`, `Mode`, `Command`, `Binary` — `State` and
   `Mode` are hidden because the conditional `Flags` column already carries their
   signal (§ Session Flags). Use `--wide` to show all 11 columns, or `--columns` to
   select a custom subset.
2. **Queued CLR Processes** — caption: `Queued · N waiting`; columns: `#`, `PID`,
   `CWD`, `Waiting`, `Attempt`. Shows `clr` processes currently blocked in
   `wait_for_session_slot()`. Column selection (`--columns`/`--wide`) does not
   affect queued table columns.
3. **Ended Since Last Check** — caption: `Ended Since Last Check · N ended (last
   check <duration> ago)`; columns: `#`, `PID`, `Ran for`, `Absolute Path`, `Task`.
   Shows sessions present in the previous `clr ps` snapshot that are no longer
   running — see § Session Snapshot & Temporal Diff. Rows ordered by PID
   ascending (no finer-grained "when did it end" signal is available — only one
   prior snapshot is ever retained). Printed after the Active/Queued tables,
   preceded by a blank line, only when a prior snapshot exists AND ≥1 tracked
   session has ended; absent otherwise (including `clr ps`'s very first-ever
   invocation, which has no prior snapshot to compare against). Suppressed under
   `--inspect`, same as the Queued table.

Plain-style formatting: no outer borders; dash separator under header row; 2-space
column gaps. Header row uses plain text (no Unicode box-drawing characters).

Table width: on a TTY, tables auto-fit to the detected terminal width (BUG-537);
piped/redirected (non-TTY) output uses a fixed 120-column fallback, so scripted
consumers see stable rendering. A `COLUMNS=<n>` variable passed to the process
(e.g. `COLUMNS=200 clr ps` — the shell's own `COLUMNS` is not exported to children)
overrides detection. Verify: compare `clr ps` on a wide terminal against `clr ps | cat`.

Row ordering: active rows ordered by session start time, oldest first (lowest epoch in `/proc/{pid}/stat` field 22); queued rows ordered by PID ascending; ended rows ordered by PID ascending.

`Elapsed` / `Waiting` / `Ran for` column format: `< 60 s` → `"45s"` | `< 1 h` → `"8m 30s"` | `≥ 1 h` → `"2h 15m"`.

Empty-state rules: no sessions and no queue → prints `No active Claude Code sessions.` only; sessions present, no queue → active table only; queue present → active section + blank line + queued table. The Ended Since Last Check table is orthogonal to all of the above — appended (blank line + table) whenever it applies, independent of whether the active/queued sections printed the empty-state sentinel or real tables.

Data sources: `/proc/{pid}/stat` (state, CPU, start time), `/proc/{pid}/status` (RAM), `~/.claude/projects/` JSONL (Task column), `/proc/{pid}/fd/0` (interactive TTY fallback), `$CLR_GATE_DIR` (default `/tmp/clr-gate/`) for queued processes. Path shortening: `$PRO` prefix is replaced by `"$PRO"` literal in path columns when set.

The current `clr ps` process is never listed as a row (self-exclusion).

### Gate State Files

`gate.rs` writes a JSON state file to `$CLR_GATE_DIR/{pid}.json` when a `clr` process
enters `wait_for_session_slot()`. The file is updated each polling iteration and removed
automatically by a `GateFile` RAII Drop guard on normal return, panic, and Rust-level
stack unwind. The Drop guard does not protect against SIGKILL, other fatal signals, or
`std::process::exit()` (all bypass destructors — including the gate's own exhaustion-path
`exit(1)`) — the liveness filter in `build_queued_table()` handles those cases.

File format:

```json
{"cwd": "/path/to/cwd", "since": 1720000000, "starttime": 5561004, "attempt": 3, "message": "waiting for session slot"}
```

- `cwd` — working directory of the waiting `clr` process
- `since` — Unix timestamp when waiting began
- `starttime` — the writer's own `/proc/{pid}/stat` field 22 (clock ticks since boot), binding the file to that process incarnation; optional — files written by pre-BUG-488 binaries lack it
- `attempt` — current poll iteration (0-based)
- `message` — human-readable status string

<!-- BUG-479 — fixed: self-heal covers unreaped zombies (state Z), not only absent PIDs; shared predicate gate::pid_alive() -->
<!-- BUG-488 — fixed: pid_alive( pid, recorded_starttime ) enforces the leader/incarnation clauses; the filter passes each waiter record's own recorded start time (None for legacy files), so thread-masked and recycled PID numbers self-heal instead of rendering as phantom Queued rows (observed live pre-fix: 76h) -->
`build_queued_table()` checks liveness for every gate file's recorded PID before rendering a row, via the shared `gate::pid_alive()` predicate, passing the record's own recorded `starttime` when the file carries one (contract: INV-012 — `/proc/{pid}/stat` readable AND state not `Z` AND the number still identifies the recording process itself: thread-group leader, same incarnation — not merely some live occupant of the same PID number). Gate files whose recorded process is gone, exited-but-unreaped (zombie), or whose PID number is now occupied only by a non-leader thread of an unrelated process or a different process incarnation are filtered out and deleted (self-healing cleanup) — this prevents orphaned gate files from SIGKILL, crash, or `exit(1)`-under-a-non-reaping-supervisor appearing as phantom waiters.

### Inspect Output

When `--inspect` is active, each matching session produces a key:value record block
separated by a blank line. Table rendering is bypassed entirely. The Queued CLR
Processes table is suppressed. `--columns` and `--wide` are ignored. Example block:

```
──── PID 1234567 ─────────────────────────────────────────────
pid:      1234567
mode:     interactive
elapsed:  72h 18m
cpu:      0.6%
ram:      96M
state:    S
path:     $PRO/lib/wip_core/agent_kit/claude_runner/module/claude_runner/src
task:     explore current crate, its documents
binary:   /usr/local/bin/claude
cmd:      --effort max --dangerously-skip-permissions
cmdline:  /usr/local/bin/claude --effort max --dangerously-skip-permissions
started:  1750170000
```

Attributes: `pid`, `mode`, `elapsed`, `cpu`, `ram`, `state`, `path`, `task`,
`binary`, `cmd`, `cmdline`, `started` (12 total). `started` is Unix epoch seconds.
`--pid` and `--mode` filters apply normally when combined with `--inspect`.

### Session Flags

Each active session row may carry zero or more flag emoji in a conditional `Flags` column.
The column is inserted immediately after the first of `state`, `ram`, `cpu`, `elapsed`,
`pid`, `idx` present in the selected column set — `state` for `--wide` and any explicit
`--columns` naming it, `ram` for the default view — falling back to leftmost when the
selection contains none of them. It is rendered in a **two-pass** approach:

1. **First pass:** compute flags for every session row.
2. **Second pass:** if all rows have empty flags, omit the `Flags` column entirely from the rendered table; otherwise include it.

When ≥1 flag is present in any row, a **legend** is printed below the active sessions table as a
single line listing only the symbols that appear in the current output (not all 10 symbols).
Format: `<emoji> <Name>` entries separated by two spaces, in canonical order 👈🆕🖨🔌⚡🕰🐘🧟⚠🐳.
Example: `🖨 Print mode  🐘 High RAM  ⚠ Dead metrics  🐳 Container`.

Two flags subsume what used to be dedicated columns, which is why neither `State` nor
`Mode` is shown by default: 🖨/🔌 are derived from the same `classify_mode()` call the
`Mode` column reads (a `Mode` cell can therefore only restate a flag or say
`interactive`, the silent default — and the caption already prints the mode census),
and 🧟 covers every kernel state worth noticing (`S` is every idle session; sustained
`R` is reported more reliably by ⚡). Use `--columns state,mode` to see the raw letter
and mode string.

| Flag | Name | Condition | Default threshold |
|------|------|-----------|-------------------|
| 👈 | This session | `getppid()` of the `clr ps` process resolves to a `claude` process | — |
| 🆕 | New since last check | PID absent from the previous `clr ps` snapshot (see § Session Snapshot & Temporal Diff) | — |
| 🖨 | Print mode | session cmdline contains `--print` or `-p` | — |
| 🔌 | Query mode | session cmdline carries the control-session signature: adjacent `--input-format stream-json` and `--output-format stream-json` pairs plus a bare `--verbose` (see § Mode Detection) | — |
| ⚡ | Active | CPU delta ≥ 3 ticks in 1-second sample window (`/proc/{pid}/stat` fields 14+15 read twice, 1 s apart) | — |
| 🕰 | Ancient | `elapsed_secs > CLR_PS_ANCIENT_SECS` | 28800 (8 h) |
| 🐘 | High RAM | `ram_mb > CLR_PS_HIGH_RAM_MB` | 400 MB |
| 🧟 | Odd state | `/proc/{pid}/stat` field 3 is neither `R` nor `S` — `D` uninterruptible, `T`/`t` stopped/traced | — |
| ⚠ | Dead metrics | `read_process_metrics()` returned `None` — the process exited between the `/proc` scan and the read (all metric fields show `-`) | — |
| 🐳 | Container | `cwd` does not start with `$HOME` | — |

🧟 and ⚠ are disjoint, not overlapping: 🧟 means the metrics parsed and reported an
abnormal state letter; ⚠ means the `/proc` read failed outright, so there is no state
letter to report.

A zombie (`Z`) matches 🧟's condition but never actually reaches it: the kernel clears
`cmdline` on exit, and step 1's scan keeps only processes whose argv[0] basename is
`claude`, so a zombie is dropped at discovery before any flag is computed. In practice
🧟 surfaces `D`, `T`, and `t` — a session blocked in an uninterruptible syscall, or one
suspended with Ctrl-Z / under a debugger.

**Threshold env vars:**

| Variable | Type | Default | Notes |
|----------|------|---------|-------|
| `CLR_PS_ANCIENT_SECS` | u64 | 28800 | Seconds elapsed before 🕰 fires; invalid values silently ignored |
| `CLR_PS_HIGH_RAM_MB` | u64 | 400 | RSS megabytes before 🐘 fires; invalid values silently ignored |

**Implementation note:** `getppid()` is obtained via `std::os::unix::process::parent_id()`.
The 👈 flag fires only when the parent process basename (read from `/proc/{ppid}/cmdline`) equals `claude`.
If `clr ps` is invoked from a shell, the parent is `bash` (or similar) and the flag is absent.

### Session Snapshot & Temporal Diff

`clr ps` persists the process list from each invocation to a snapshot file, so
the *next* invocation can report what changed: the 🆕 (New since last check)
flag on the active table, and the Ended Since Last Check table for sessions
that vanished. This is always-on — there is no flag to disable it — and has no
effect on any table's content beyond the flag/table it drives.

**State file location:** `$CLR_PS_STATE_DIR/last_snapshot.json`, default
`~/.clr/ps/last_snapshot.json` (mirrors `~/.clr/config.toml`'s home-relative
convention). `CLR_PS_STATE_DIR` overrides the directory — used in tests to
isolate snapshot I/O from real system state, same rationale as `CLR_GATE_DIR`
for gate files.

File format:

```json
{
  "captured_at": 1720000000,
  "sessions": {
    "1234567": { "started_at": 1719950000, "path": "/home/user/project", "task": "explore current crate" }
  }
}
```

- `captured_at` — Unix timestamp when this snapshot was written
- `sessions` — map of PID (string key) → tracked session; `started_at` is the
  process start time (`null` on non-Linux, where no `/proc`-derived start time
  is available — mirrors this command's existing `-` convention for every
  other metrics-derived column); `path` is the raw (unshortened) working
  directory — `$PRO` shortening is applied when the Ended table renders, not
  when the snapshot is written; `task` is the same Task-column value described
  in § Output Format

**Write trigger:** every `clr ps` invocation reads the existing snapshot (if
any) for its own 🆕/Ended computation, then unconditionally overwrites it with
the current process list — including under `--inspect`, so a later non-inspect
call still sees accurate state even if the invocations in between were all
`--inspect`. The write is best-effort (temp file + rename) and never aborts
the command: a full disk or unwritable state directory silently skips the
write rather than failing `clr ps` itself.

**First invocation:** with no snapshot file yet, 🆕 never fires (there is
nothing to compare against — showing every session as "new" on the very first
call would be noise, not signal) and the Ended table never appears.

**Scope note:** the snapshot always reflects the *full*, unfiltered process
list — never the `--pid`/`--mode`-filtered view. A filtered `clr ps --pid
1234567` invocation still writes the complete session set, so it never makes
untouched sessions look "ended" on a later, unfiltered call.

### Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Success — table(s) or inspect blocks printed, or no-sessions message printed |
| 1 | Error (invalid `--mode` value, unknown `--columns` key, non-numeric `--pid` value, or unexpected I/O failure) |

### Mode Detection

Each active session is classified as `query`, `print`, or `interactive` by examining its NUL-delimited `/proc/{pid}/cmdline` arguments, in that priority order. If the arguments contain the adjacent pairs `--input-format stream-json` and `--output-format stream-json`, plus a bare `--verbose` flag, the session is classified as `query`. Otherwise, if any argument equals `--print` or `-p`, the session is classified as `print`; otherwise `interactive`. The `--mode` filter uses this classification to include or exclude rows.

### Examples

```sh
# List all running sessions and queued waiters
clr ps

# Show only print-mode (headless) sessions
clr ps --mode print

# Show all 11 columns, including the State, Mode, Command and Binary columns
# that the default view leaves to the Flags column
clr ps --wide

# Bring back just the two columns the Flags column subsumes
clr ps --columns idx,pid,elapsed,cpu,ram,state,mode,path,task

# Custom column selection in specified order
clr ps --columns pid,path,mode,task

# Wide output filtered to interactive sessions only
clr ps -w --mode interactive

# Filter to specific PIDs
clr ps --pid 1234567
clr ps --pid 1234567,2345678

# Inspect full attributes of all sessions
clr ps --inspect

# Inspect specific session
clr ps --pid 1234567 --inspect

# Show ps-specific help
clr ps --help

# Env-var equivalents
CLR_PS_MODE=print clr ps
CLR_PS_COLUMNS=pid,elapsed,cmd clr ps
CLR_PS_PID=1234567 clr ps

# Isolate snapshot state (used in tests to avoid touching ~/.clr/ps)
CLR_PS_STATE_DIR=/tmp/my-ps-state clr ps

# Discover known subcommands (ps appears in help)
clr help
```

### Notes

`ps` is Linux-only; per-process metrics come from `/proc` and are not available on macOS or Windows. On non-Linux platforms the command is not compiled in.

The Task column shows the last Form A (plain-string content) user message from
the session's JSONL log, truncated to 35 chars. Form A messages have structure
`{"type":"user","message":{"role":"user","content":"<text>"}}`. Form B messages
(`"content":[...]` array — tool_result / skill invocations) are skipped. Falls
back to `interactive` when no JSONL is found or no Form A entry is present.

`clr p` and `clr pss` trigger the "Did you mean 'ps'?" typo guard and exit 1.

The `CLR_GATE_DIR` environment variable overrides the default `/tmp/clr-gate/` gate
state directory — used in tests to isolate gate file I/O from real system state.

`query` sessions (started via `clr query "<message>"`) appear in the active sessions
table like any other `claude` process, classified as `query` mode rather than
`interactive` or `print` — see § Mode Detection.
